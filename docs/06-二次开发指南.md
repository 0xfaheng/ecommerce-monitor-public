# 二次开发指南

## 1. 接入自己的产品库

将 `examples/product_library.sample.csv` 替换为自己的私有产品库。建议至少包含：

- 产品名称。
- 规格。
- 品牌或厂家。
- 平台范围。
- 必须命中的关键词。
- 是否启用。

真实产品库不要提交到 public 仓库。

## 2. 实现平台适配器

在自己的私有项目中实现 `PlatformAdapter`：

```python
class MyAdapter(PlatformAdapter):
    def collect(self, plan):
        ...
```

适配器只返回统一的 `ListingCandidate`，不要把平台细节泄漏到后续业务模块。

## 3. 实现规则库

规则建议拆成配置或表格，而不是写死在代码中。

常见规则：

- 店铺级排除。
- 商品 ID 排除。
- 标题关键词排除。
- 平台差异化规则。
- 人工复核规则。

## 4. 接入外部表格

外部表格负责人工确认和状态回写。建议字段名稳定，避免后续流程依赖页面展示顺序。

关键字段：

- 采集日期。
- 平台。
- 商品标题。
- 商品链接。
- 店铺。
- 企业。
- 区域。
- 负责人。
- 确认状态。
- 推送状态。

## 5. 接入通知系统

通知系统建议支持两种模式：

- dry-run：只生成将要发送的内容，不真实发送。
- send：真实发送，并回写状态。

推送失败要区分：

- 临时失败，可以重试。
- 路由缺失，需要人工补齐。
- 权限失败，需要检查机器人或目录权限。

## 6. 增加操作台

操作台可以展示：

- 当前配置摘要。
- 最近运行 manifest。
- 登录状态或授权状态。
- 手动触发采集。
- 手动触发 dry-run。
- 查看失败原因。

操作台不应展示密钥原文。

## 7. 测试建议

至少覆盖：

- 字段归一化。
- 去重键生成。
- 规则排除。
- 客户匹配。
- 人员路由。
- dry-run 结果。
- 推送状态回写。
- 敏感信息扫描。
