# 脱敏与公开边界

本仓库是从内部项目理念整理出的 public 版，不包含内部 Git 历史。

## 已移除内容

- 真实人员姓名和 open_id。
- 真实客户、店铺、企业名称。
- 真实商品 ID、平台链接、排除名单。
- 真实飞书/Lark Base token、table id、chat id。
- 真实机器人 app id、app secret、webhook。
- 真实生产服务器 IP、SSH 用户、部署路径。
- 真实数据库、日志、运行 manifest、截图证据。
- 内部任务记录、发布记录、故障记录。

## 保留内容

- 模块划分。
- 流程状态机。
- 字段结构。
- 配置项名称。
- dry-run 思路。
- 人工确认边界。
- 运行审计思路。

## 为什么不保留原 Git 历史

私有项目的历史提交可能包含：

- 已删除但仍可从历史恢复的 token。
- 早期部署脚本或服务器路径。
- 内部排查记录。
- 业务规则演进。
- 人员、客户、店铺、商品信息。

公开仓库应从干净初始提交开始，避免把历史风险带到 public 网络空间。

## 发布前检查清单

- `git grep` 没有真实密钥、token、open_id、chat_id。
- `git log --all` 不包含私有历史。
- `.env`、数据库、日志、截图、manifest 未进入 Git。
- README 没有真实客户和人员。
- 示例数据全部虚构。
- GitHub 仓库 visibility 确认是 public。
- 生产凭据已确认不在公开仓库中。
